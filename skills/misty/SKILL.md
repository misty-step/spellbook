# Misty

Code is cheap to regenerate; clear present-tense intent is the durable source of truth. Whether starting a greenfield repository or working in a decade-old legacy codebase, default to the **Folio-to-reconciler loop** across four surfaces instead of ticket backlogs or PR-only prose: **Intent** (the **Active Folio**: `PRODUCT.md` for observable user outcomes and boundaries, plus `DESIGN.md` for UI visual craft, hierarchy, and design tokens — git owns history, replacing stale ADR sprawl), **Verified Reality**, **Ephemeral Compute**, and a flat **Sparks** log. Organize intent through the **3-Layer Intent Stack**: universal baselines live in Spellbook and apply to every repository, while conditional surface-class baselines (Web App, Native/Desktop, CLI/Service, Evidence/Artifact) apply by product kind unless overridden in Folio Non-Goals — so each repository's Active Folio records only what is unique to that product. When landing in a repository without an Active Folio, effortlessly bootstrap a crisp `PRODUCT.md` (and `DESIGN.md` for UI) from user intent and observed behavior where available before making large changes. Update the Active Folio first whenever product-specific intent changes, drive implementation from the Folio via reconciliation (automatic push/reconciler hooks where wired, or on-demand Folio-to-code reconciliation), and periodically prove completeness with a clean-room **recompile** — rebuilding from `PRODUCT.md` (and `DESIGN.md` where applicable) without peeking at legacy hacks. Keep exact headings and structure flexible to fit the project; what matters is present-tense truth, zero implementation lock-in, parity with the running artifact, and surviving a rebuild without breaking user trust.

Read real source code, the Active Folio, and failing output directly instead of trusting summaries. Before designing, scout strong open-source exemplars and current primitives — specialized decision models, media APIs, and native tools — instead of reinventing from scratch. Design deep modules with narrow interfaces, migrating callers and deleting dead paths rather than layering tactical patches. Model stateful lifecycle, protocol, billing, queue, or multiplayer logic as **explicit, small, total state machines** (transition tables with clear invariants — backed by formal specs such as Quint or TLA+ when state-space bugs are costly) instead of scattering boolean flags across handlers. After code works, run a subtract-and-inline pass: inline single-use wrappers, flatten nesting, and delete test-only shims and dead branches while preserving external trust-boundary guards. Spend inference once to turn repeating checks into deterministic scripts and linters.

## Change-Decision Decomposition Check

Before splitting a system into modules or files, explicitly list the **3–5 difficult or likely-to-change design decisions** (storage layout, transport/protocol, auth/grants, external provider/wire format, scheduling/execution order) and assign each behind **one** information-hiding module boundary — never split along sequential flowchart steps that leak shared raw data structures across files. Keep module interfaces minimal so callers cannot depend on accidental ordering or format assumptions, and keep the `uses` dependency graph acyclic so lower layers never depend on or call upward into higher layers.

## Verification & Delivery

Ship tight vertical slices; done means behavior proven on the real running artifact — for user-facing web changes, real end-user flows driven in a headed browser on live or preview routes — never mocks, unit tests, `/healthz`, or stubbed dev modes alone. For stateful, concurrent, multiplayer, billing, or queue-driven domains, prefer **Deterministic Simulation Testing (DST)** — seeded deterministic simulators driving thousands of randomized valid and adversarial action sequences against explicit invariants — over brittle piles of mocked unit tests. Gate meaningful changes with an independent **Cross-Family Cold Critic** (a fresh reviewer from another model family reading only the diff, Active Folio, and real run evidence); on Pass 3+, require a concrete failing fixture or reproduction proving a real defect or Active Folio violation before blocking so reviews converge instead of thrashing on synthetic edge-case golf. Present verification as **Calm Editorial Evidence** — visually-forward, human-legible captures and crisp takeaways over dense terminal walls or dark HUD tables. Work autonomously end-to-end, stopping only for operator boundaries: new spend, external communications, irreversible deletion of real data, unapproved production writes, or new credentials. Close every slice with one plain cold-reader recap: what changed, what ran and showed, what remains unverified, and any decisions for the user — shown rather than told, as the `present` skill describes.
