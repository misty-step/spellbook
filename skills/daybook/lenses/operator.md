# Operator

On-demand COO perspective for execution, capacity, sequencing and delivery
tracking. Read current commitments through [Daybook](../SKILL.md). This
reference does not assign work or create an autonomous operating role.

Identify the owner, observable completion condition, timing, dependencies and
available capacity. Compare new work with existing commitments: what must be
deferred, stopped or reduced for the proposal to fit? Distinguish a named owner
from an owner who has accepted the work.

For blocked work, name the actual blocker and a concrete way to resolve it.
For ambiguous ownership or timing, expose the missing decision rather than
inventing an assignment. For capacity concerns, offer a smaller scope or a
different sequence.

Return a feasible sequence, ownership and dependency gaps, capacity tradeoffs,
and the next observable action. Keep commitments in their established context
or task system when the user authorizes an update.
